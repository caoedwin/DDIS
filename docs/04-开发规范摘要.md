## 4.1 后端代码规范

### 4.1.1 Django 版本约束

- **Django 2.1.7** —— 不可随意升级。
- 可用 API：
  - `from django.conf.urls import url`（仍可用，但新代码建议 `re_path`）
  - `from django.urls import path, include, re_path`
  - `path()` 支持 `<str:param>` / `<int:param>` 转换器
- **Python 3.12.9** —— 与 Django 2.1.7 存在兼容性风险，修改核心代码需谨慎测试。

### 4.1.2 视图（Views）

- **以函数视图为主**（Function-Based Views）。
- POST 请求使用 `@csrf_exempt` 装饰器，或正确处理 CSRF Token。
- **登录状态检查**：每个视图函数开头：
  ```python
  if not request.session.get('is_login', None):
      return redirect('/login/')
  ```
- 视图函数命名：下划线风格，如 `CDM_upload`、`CDM_search`、`CDM_edit`。
- 标准模式：

  ```python
  from django.shortcuts import render, redirect
  from django.views.decorators.csrf import csrf_exempt

  @csrf_exempt
  def CDM_upload(request):
      if not request.session.get('is_login', None):
          return redirect('/login/')
      # ... 业务逻辑
      return render(request, 'CDM/CDM_upload.html', context)
  ```

### 4.1.3 模型（Models）

- 模型类名：**PascalCase**，如 `CDM`、`CQM`、`PersonalInfo`。
- 字段名：**PascalCase / 混合命名**，如 `Customer`、`Project`、`SKU_NO`、`edit_time`。与现有代码保持一致。
- 每个模型类定义 `Meta` 内部类：

  ```python
  class CDM(models.Model):
      Customer = models.CharField(max_length=20)
      Project = models.CharField(max_length=20)

      class Meta:
          verbose_name = 'CDM'
          verbose_name_plural = verbose_name

      def toJSON(self):
          fields = []
          for field in self._meta.fields:
              fields.append(field.name)
          d = {}
          for attr in fields:
              d[attr] = getattr(self, attr)
          import json
          return json.dumps(d)
  ```

- `toJSON(self)` 方法为旧约定，DRF 模块用 `ModelSerializer` 替代。

### 4.1.4 URL 路由

- 根 [urls.py](../Reliability_Row_data/urls.py) 使用 `path()` 和 `re_path()` 注册路由。
- 每个业务模块使用 `include()` 引入子路由，并指定 `namespace`：

  ```python
  path('CDM/', include('CDM.urls', namespace='CDM')),
  ```

- 模块内 `urls.py` 必须定义 `app_name`，并使用 `path()` 定义具体路由：

  ```python
  # CDM/urls.py
  from django.urls import path
  from . import views
  app_name = 'CDM'

  urlpatterns = [
      path('CDM-upload/', views.CDM_upload, name='CDM_upload'),
      path('CDM-edit/', views.CDM_edit, name='CDM_edit'),
      path('CDM-update/<int:id>/', views.CDM_update, name='CDM_update'),
      path('CDM-search/', views.CDM_search, name='CDM_search'),
      path('CDM-export/', views.CDM_export, name='CDM_search'),
  ]
  ```

- 权限白名单在 [settings.py](../Reliability_Row_data/settings.py) 的 `SAFE_URL` 中配置（正则匹配）。

### 4.1.5 DRF 序列化器

- 使用 `ModelSerializer`，`fields = "__all__"` 模式：

  ```python
  from rest_framework import serializers
  from .models import *

  class CQMserilizer(serializers.ModelSerializer):
      class Meta:
          model = CQM
          fields = "__all__"
  ```

### 4.1.6 认证与权限

- **Session 认证**：默认方式，通过 `request.session` 存储用户状态。
- **JWT 认证**：使用 `djangorestframework-simplejwt 5.2.0`，配置在 `settings.SIMPLE_JWT`。
- **RBAC 权限**：通过 [middleware/checkper.py](../middleware/checkper.py) 的 `RbacMiddleware` 实现 URL 级权限控制。
- **权限白名单**：`settings.SAFE_URL` 列表中的 URL 正则匹配可跳过权限检查。
- Session 配置：`SESSION_ENGINE = 'django.contrib.sessions.backends.db'`。

### 4.1.7 Celery 任务

- Celery 配置在 [settings.py](../Reliability_Row_data/settings.py) 底部。
- Broker：Redis (db=1)，Result Backend：Redis (db=2)。
- 定时任务通过 `CELERY_BEAT_SCHEDULE` 配置。
- 异步任务定义在各模块的 `tasks.py` 中，使用 `@task` 装饰器（注意是 `from celery.task import task`）。

### 4.1.8 日志

- 日志配置在 `settings.LOGGING`。
- 日志目录：项目根目录 `logs/`。
- 日志格式：`[时间] [文件:行号] [模块:函数] [级别] - 消息`。
- 按日期滚动，单文件最大 5MB，保留 5 个备份。
- 业务代码使用 `logging.getLogger('log')` 写日志。

### 4.1.9 文件上传

- Media 根目录：`c:/media`（原始字符串）。
- 最大内存上传：1GB（`FILE_UPLOAD_MAX_MEMORY_SIZE = 524288000 * 2`）。
- 临时目录：`/media/temp`。

## 4.2 前端代码规范

### 4.2.1 Vue.js 版本约束（**严禁违反**）

- **Vue.js 2.6.10** —— 严禁使用 Vue 3 语法。
- 不使用 Composition API（`setup()`、`ref()`、`reactive()`）。
- 使用 **Options API**（`data()`、`methods`、`computed`、`watch`）。
- Vue 源码位于：`static/download_UPK/vue@2.6.10/dist/vue.js`。

### 4.2.2 Element UI 版本约束（**严禁违反**）

- **Element UI 2.12.0** —— Vue 2 专用组件库。
- 不是 Element Plus（Element Plus 是 Vue 3 版本）。
- CSS 引入：`static/download_UPK/element-ui@2.12.0/lib/theme-chalk/index.css`。
- 组件示例：`<el-table>`、`<el-form>`、`<el-button>`、`<el-dialog>` 等。

### 4.2.3 前端引入方式

- **无构建工具** —— 不使用 webpack/vite/rollup。
- 所有 JS/CSS 通过 `<script>` 和 `<link>` 在 Django 模板中直接引入。
- Axios：`static/js/axios.min.js`。
- Vue：`static/download_UPK/vue@2.6.10/dist/vue.js`。
- Element UI：`static/download_UPK/element-ui@2.12.0/lib/index.js`。

### 4.2.4 模板规范

- 所有页面模板继承 [base.html](../templates/base.html)：`{% extends 'base.html' %}`。
- 模板区块：
  - `{% block title %}` —— 页面标题
  - `{% block css %}` —— 页面样式
  - `{% block content %}` —— 页面内容
  - `{% block style %}` —— 额外样式
- Django 模板标签：`{% load staticfiles %}`、`{% csrf_token %}`、`{% url 'namespace:name' %}`。

### 4.2.5 主题切换

- 支持 **深色/浅色** 主题切换（右上角按钮）。
- `body` 上动态添加 `theme-light` / `theme-dark` class。
- **禁止硬编码颜色** —— 使用 CSS 变量或依赖主题 class。
- 禁止内联 `style="color: white;"` 等固定颜色。
- 子页面背景使用 `rgba()` 半透明，不要固定背景。

### 4.2.6 Vue 实例模式

```javascript
new Vue({
    el: '#app',
    data() {
        return {
            tableData: [],
            form: {},
            loading: false
        }
    },
    methods: {
        fetchData() {
            axios.post('/CDM/CDM_search/', {
                // ...
            }).then(res => {
                this.tableData = res.data
            })
        }
    },
    mounted() {
        this.fetchData()
    }
})
```

### 4.2.7 Axios 请求

- 全局使用 Axios（非 fetch API）。
- POST 请求需携带 CSRF Token（通过 `Qs.stringify` 或 FormData）。
- 请求 URL 使用相对路径，如 `/CDM/CDM_search/`。
- 响应数据格式：直接返回 JSON。

## 4.5 禁止事项（**严格遵守**）

### 5.1 通用禁止

1. **禁止使用 Vue 3 语法** —— 不使用 `<script setup>`、`ref()`、`reactive()`、`defineProps()`。
2. **禁止使用 Element Plus** —— 只能用 Element UI 2.12.0。
3. **禁止使用 React** —— 前端框架是 Vue 2。
4. **禁止引入 npm/webpack 构建工具** —— 前端无构建步骤。
5. **禁止升级 Django 版本** —— 项目锁定 Django 2.1.7。
6. **禁止使用 Django 2.2+ 的 API** —— 如 `jsonfield` 改为 `django_jsonfield`。
7. **禁止在模板中硬编码颜色** —— 使用主题 CSS 变量。
8. **禁止使用 TypeScript** —— 前端纯 JavaScript。

### 5.2 必须遵守

1. **新模块必须遵循标准目录结构**（models/views/urls/admin/forms）。
2. **视图函数必须检查登录状态**（`request.session.get('is_login')`）。
3. **POST 请求使用 `@csrf_exempt`** 或正确处理 CSRF Token。
4. **URL 路由必须注册 namespace**（如 `namespace='CDM'`）。
5. **敏感信息（密码/密钥）已在 settings.py 中** —— AI 辅助开发时不要暴露到前端。
6. **模型字段命名保持 PascalCase** —— 与现有代码保持一致。
7. **模板必须继承 base.html** —— 确保主题/导航一致。
8. **日期时间处理注意时区** —— `TIME_ZONE = 'Asia/Shanghai'`，`USE_TZ = False`。

## 4.6 常见坑点与最佳实践

### 4.6.1 base.html 修改陷阱

**坑**：直接修改 `base.html` 的全局 CSS 会影响所有子页面样式，导致 `.wrap-text:hover`、`.my-table` 等失效。

**最佳实践**：
- 修改 `base.html` 时使用 scoped class（仅作用于 base.html 自身元素）。
- 外部资源路径（如 `/static/js/vendor/datatables/jquery.dataTables.js`）必须有效，避免 404。
- 修改前先备份为 `base_YYYYMMDD_xxx.html`。
- 出问题时立即回滚到 `base20250911backup.html`（已知可正常工作版本）。
- 不要在模板中混入会被 Django 渲染的 `<` 字符，否则触发 `Uncaught SyntaxError: Unexpected token '<'`。

### 4.6.2 Session 序列化陷阱

**坑**：Django 默认 session 用 JSON 序列化，不能存复杂对象。

**最佳实践**：项目已设置 `SESSION_SERIALIZER = 'django.contrib.sessions.serializers.PickleSerializer'`，可存任意 Python 对象。但新代码仍建议只存简单 dict/list/str。

### 4.6.3 时区陷阱

**坑**：`USE_TZ = False`，所有 DateTimeField 在 DB 中是 naive datetime。

**最佳实践**：
- 业务代码用 `datetime.datetime.now()`（本地时间）。
- 不要混用 `timezone.now()`（在 `USE_TZ=False` 时与 `now()` 行为一致，但避免混淆）。
- 模板渲染时直接显示，无需 `|timezone:"Asia/Shanghai"`。

### 4.6.4 Celery 任务陷阱

**坑**：任务内 `print` 不会输出到日志文件，只输出到 Worker 终端。

**最佳实践**：
- 任务内用 `logging.getLogger('log').info(...)` 写日志。
- 长时间任务要捕获异常并返回状态，避免 Worker 卡死。
- 启动多个 Celery 时必须用不同 Redis DB。

### 4.6.5 权限 URL 正则陷阱

**坑**：`Permission.url` 是正则字符串，`/CDM/CDM_search/` 与 `/CDM/CDM-search/`（下划线 vs 连字符）会被视为不同 URL。

**最佳实践**：
- 新增权限时仔细核对 `urls.py` 中 `name=` 与路径字符串。
- 注意 `re.match` 是从开头匹配，不需要 `^`。
- `SAFE_URL` 中的 `.*` 会贪婪匹配，注意范围。

### 4.6.6 文件上传路径陷阱

**坑**：`MEDIA_ROOT = r'c:/media'`，不是项目内 `media/` 目录。

**最佳实践**：
- 测试上传功能时确认写到 `c:\media`，不是项目目录。
- 部署到新机器时必须创建 `c:\media` 目录并赋权。
- `MEDIA_URL = '/media/'`，访问 URL 是 `http://host/media/xxx`。

### 4.6.7 前端 CSRF Token 陷阱

**坑**：POST 请求未携带 CSRF Token 会被 `CsrfViewMiddleware` 拦截返回 403。

**最佳实践**：
- 视图使用 `@csrf_exempt` 装饰器跳过检查（项目主流做法）。
- 或在模板中 `{% csrf_token %}` 并在 axios 中通过 `Qs.stringify` 提交。
- DRF API 模块使用 JWT，不受 CSRF 影响。

### 4.6.8 Channels 与 runserver 陷阱

**坑**：使用 `python manage.py runserver` 启动时 WebSocket 不可用。

**最佳实践**：
- 需要 WebSocket 时必须用 Daphne：`daphne -b 0.0.0.0 -p 8000 Reliability_Row_data.asgi:application`。
- 或双击 `ChannelsServer.bat`（注意其端口是 8700，生产部署需修改）。
- 开发 HTTP 接口时可用 runserver，调试 WebSocket 时切换到 Daphne。

### 4.6.9 Exchange 邮件账号陷阱

**坑**：`OAmail_account.json` 中账号密码以逗号分隔存储，格式特殊。

**最佳实践**：
- 修改时保持原格式：`username,password`（无空格）。
- 文件权限应限制为仅服务账号可读。
- 不要把账号密码硬编码到 [app01/tasks.py](../app01/tasks.py) 中。

### 4.6.10 MongoDB 连接陷阱

**坑**：`mongoengine.connect()` 在 settings.py 顶部执行，连接失败会导致 Django 无法启动。

**最佳实践**：
- 启动前确认 MongoDB 服务可达。
- 若业务不依赖 MongoDB，可临时注释 `mongoengine.connect()` 行排查问题。
- `mongotest` 模块仅用于测试，不要在生产环境暴露其 URL。
